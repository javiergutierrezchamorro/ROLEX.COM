# ROLEX for MS-DOS -- PHOTOREALISTIC Screen Clock (Mode 13h)

An open-source clone of the `ROLEX.COM` screensaver by RIX SoftWorks (1985, 1986), updated with a real photograph: a steel Rolex Oyster Perpetual Datejust against a black background, featuring a clean dial (without hands) onto which the hours, minutes, seconds, and current date are rendered in real time.

Like me even before [Guardatiempo](https://guardatiempo.com/), many of you will recall computer store windows in the late 1980s and early 1990s displaying a Rolex clock showing the actual time. It was either that or the Landmark Speed Test. As a watch enthusiast, that left a lasting impression on me: a Rolex Oyster Quartz running on a colorful DOS screen. I tried programming something similar multiple times—first in Turbo BASIC 1.1, later in Turbo C 2.0 using `EGAVBA.BGI`, and eventually in Turbo Pascal 6 with inline assembly. All of those attempts remained incomplete.

The original development by RIX Softworks, Inc. in Turbo Pascal 3 (1985) ran in EGA mode at 640x350 resolution with 16 colors—state of the art for its era.

This version of `ROLEX.COM` (2026) by Javier Gutiérrez Chamorro (Guti), built with OpenWatcom 2.0 (2026), runs at 320x200 resolution with 256 colors, delivering a near-photorealistic display.

While the RIX release occupied over 70 KB across two files (the main executable and screen data), this implementation bundles everything into a single COM executable weighing just 25.1 KB (23 KB compressed via UPX).

On a standard 4.77 MHz IBM PC, `ROLEX.COM` executes two to three times faster while explicitly avoiding inline assembly (`#pragma aux`). The codebase is 100% pure C, maximizing efficiency through direct hardware manipulation: writing straight to VGA VRAM at segment `0xA000`, reading keypresses and timer ticks directly from the BIOS Data Area at `0x0040`, and programming the DAC color palette registers directly.

The watch model has been updated to an automatic Rolex Datejust, with refined, realistic hand rendering and polished visual performance.

Development originated from an unfinished Borland C++ 3.1 codebase, completed collaboratively with Claude.

The dial is sourced directly from a photograph. The hands are rendered programmatically as polished steel batons updated at ~70 frames per second with smooth sweeping motion in clockwise orientation.

**What's new in this version:** The dial diameter has expanded to 170 pixels (up from 148), and **all assets are embedded directly inside the executable**. The PCX-RLE compressed image and color palette are baked into `ROLEX.COM`. No external graphic assets or DOS File I/O APIs are required; `ROLEX.COM` is fully self-contained.

## 1. System Requirements

* **MS-DOS** (or DOSBox) with **128 KB+ VGA video memory**. (Required because the hidden video page at `0xB000` serves as a off-screen workspace buffer. Standard 64 KB VGA configurations like the MCGA on PS/2 Model 30 are insufficient).
* **640 KB conventional memory**.
* **No external dependencies:** Graphics are entirely embedded.

### Package Contents

| File | Description |
| :--- | :--- |
| `ROLEX.COM` | Complete executable (25.1 KB: code + palette + RLE image). Flat binary ready to run. |
| `ROLEX.C` | Fully commented single-file source code (100% C). |
| `IMGRLE.H` | Embedded asset data (palette + RLE compressed background) and calibrated geometry parameters (generated by `prep_img.py`, included by `ROLEX.C`). |
| `BUILD.BAT` | OpenWatcom build script for DOS environments. |

## 2. Usage

```cmd
ROLEX
```
*(or `ROLEX.COM`)*

* Press **ESC** to exit. All other keystrokes are ignored.
* Date values are retrieved from the CMOS RTC during startup and updated at midnight. The clock timing derives from the BIOS tick counter. The date aperture displays the day of the month without leading zeros (e.g., `8` instead of `08`).

## 3. Building (Open Watcom v2, 16-bit)

Inside a DOS environment:
```cmd
BUILD.BAT
```

> **Note:** `BUILD.BAT` and `MAKEFILE` invoke `wcl` using compiler settings `wcc -ms` linked with `system com` / `system dos` standard libraries, equivalent to:
> ```cmd
> wcl -mt -0 -bt=dos -os -d0 rolex.c
> ```

`IMGRLE.H` must reside in the same directory as `ROLEX.C`. The resulting binary does not link the standard Watcom C runtime libraries—file loading routines and text messaging overhead are omitted. The only external system call remains `int 21h AH=2Ah` as a fallback mechanism for date retrieval if the hardware RTC fails.

## 4. Technical Architecture

* **Image Pipeline:** `IMGRLE.H` holds `PALETTE[768]` and `BACKGROUND_RLE[]`. The central horizontal band of the image (247 out of 320 columns containing visible content, bordered by pure black padding) is compressed using standard PCX RLE encoding:
  * `byte < 0xC0` $\rightarrow$ single pixel index.
  * `byte >= 0xC0` $\rightarrow$ repeat count (`byte & 0x3F`) for the subsequent pixel byte.
  
  This algorithm decompresses in a few lines of standard C code. Uncompressed pixel data totals 49,400 bytes, which compresses down to 18,836 bytes. Combined with the palette data and runtime execution logic, the final binary size remains well under the 64 KB tiny-model segment limit at 25.1 KB.

* **Video Display:** Mode 13h ($320 \times 200$, 256 colors). During initialization, VRAM is cleared to black and the compressed frame is decompressed directly onto the central region of visible memory at `A000:0000`.

* **Off-Screen Workspaces:** Segment `0xA000` addresses active display memory. Segment `0xB000` (the second hardware page) hosts the render buffers:
  * `B000:00000`: Frame rendering target buffer.
  * `B000:28900`: Clean dial cache ($170 \times 170$ background snapshot).
  
  System RAM usage is kept minimal, containing only code, palette descriptors, compressed asset payload, trigonometric lookup tables, and digit font data.

* **Flicker Mitigation:** Every frame is completely assembled within the `0xB000` workspace buffer by layering the cached clean dial, updated date window, and hand geometry. The composite frame is blitted to visible video RAM line-by-line synchronized with the vertical retrace pulse (polling port `0x03DA`), avoiding screen tearing or visible rendering artifacts.

* **Timekeeping:** Uses the BIOS timer tick counter located at `0040:006C`. The Programmable Interval Timer (PIT) triggers at $18.2065\text{ ticks/sec}$. Second calculations are evaluated using:
  $$\text{seconds} = \frac{\text{ticks} \times 2000}{36413}$$
  This maintains accurate timing without accumulation drift. Sub-second fractional remainders drive the smooth sweeping movements of the second, minute, and hour hands.

* **Hand Rendering:** Hands are rendered as filled polygonal shapes (tapered batons with defined facets and counterweights) drawn per scanline using three steel shading tones: dark outline, bright body, and light bevel facet. Calculations rely on a fixed-point Q8 sine/cosine table and integer square root routines, avoiding floating-point operations. Angle 0 points to 12 o'clock and advances clockwise. Hand dimensions scale dynamically based on dial geometry definitions provided in `IMGRLE.H`.

* **Date Aperture:** Reads CMOS RTC values directly via I/O ports `0x70`/`0x71` (polling the UIP update-in-progress bit, converting BCD to binary). Includes a fallback to `int 21h AH=2Ah`. Numbers are rendered centered in the window frame using a built-in $8 \times 8$ bitmapped font. Re-reads occur only across midnight boundaries.

* **Keyboard Input:** Reads keypresses by directly inspecting the BIOS keyboard buffer head pointer at `0040:001A` without relying on `int 16h`.

* **Palette Management:** Quantized color values from the source photo (up to 250 indices; the source image is mostly monochrome, using ~120 shades across a shared grayscale ramp) plus 6 reserved indices (250–255 for steel tones, background black, and date text white). The hardware DAC is configured directly via ports `0x03C8`/`0x03C9` (scaled to 6-bit values).

* **Image Processing:** The image generation tool (`prep_img.py`) sharpens the watch face prior to downsampling, scales using a Lanczos filter, adjusts contrast levels for maximum text legibility, and applies dual unsharp masking. Non-dithered color quantization preserves crisp detail on dial text while compressing adjacent solid areas effectively for optimal RLE ratios.

## 5. Embedded Image Data Layout (`IMGRLE.H`)

* `PALETTE[768]`: 256 RGB entries ($0\dots 255$ intensity values, divided by 4 for VGA DAC hardware registers). Indices 250–255 are reserved for hand geometry and date text rendering.
* `BACKGROUND_RLE[]`: PCX-style RLE compressed stream representing the central $247 \times 200$ frame area, stored scanline by scanline.
* `BACKGROUND_RLE_LEN`: Length of compressed stream in bytes.
* `DIAL_W/H`, `DIAL_X/Y`, `VEN_X0..Y1`, `STRIP_W/X`, `R_AG_H..CEN_PN`: Calibrated offset dimensions. The clean dial ($170 \times 170$) maps to coordinates $(75, 15)$. The date aperture occupies local rectangle $135\dots 149 \times 81\dots 88$. The main image strip is placed starting at column 43. Hand lengths scale according to calibrated dial radii.

> The clean dial image is not stored as a separate compressed asset. At initialization, the executable crops the region directly from VRAM (rows 15–184, columns 75–244) and caches it in off-screen memory.

Asset generation script (`verification/prep_img.py`) processes source imagery (`verification/fotos/reloj2.png` and `esfera.jpg`):

```bash
python3 prep_img.py [--sin-difusion]
```

This outputs `IMGRLE.H` directly to the root source directory alongside preview artifacts (`prev_*.png`). Updating source images or dial target sizes requires re-running this script and recompiling; runtime constants update automatically.

## 6. Host Verification Suite (`verification/`)

The core `ROLEX.C` source can be compiled under host GCC environments via a shim harness simulating VRAM memory buffers (`0xA000` active display and `0xB000` off-screen workspace), hardware registers, and DOS interrupt behavior. Rendered output is written directly to PPM/PNG images:

```bash
gcc -O2 -o host_rolex host_main.c
./host_rolex 10 9 36 8 11 2026 12 capture.ppm
python3 ppm2png.py capture.ppm capture.png
```

*(The host harness uses `IMGRLE.H` directly, validating the exact target logic and embedded asset payloads used by the MS-DOS binary).*

A pixel-for-pixel comparison against an independent reference engine implemented in Python validates accuracy:

```bash
python3 prueba_frames.py
```

Tests verify six distinct timestamp states (`12:00:00`, `03:00:00`, `09:15:30`, `06:30:15`, a 30-tick sweep at `10:09:36`, and the midnight transition at `23:59:50`). Current validation status: **0 mismatched pixels out of 64,000 across all test targets**, confirming clean redraw cycles without hand trail artifacts.

## 7. Version History

* **v5 (Current):**
  * Expanded dial size from 148 to 170 pixels.
  * Embedded image payload directly inside COM binary (`IMGRLE.H`).
  * Removed external `int 21h` graphics file loading dependencies.
  * Moved composite frame workspace and clean dial caches into off-screen video memory page `0xB000`.
  * Cropped image data payload to active content width (247 columns).
  * Disabled error diffusion outside the dial region to improve compression ratios and steel appearance.
  * Centered date text alignment inside the aperture window.
* **v4:**
  * Reduced `ROLEX.IMG` asset footprint from 63.3 KB to 44.5 KB by storing only the central 224-column content band.
  * Sharpened dial details via pre-scale contrast expansion and dual unsharp mask passes.
  * Formatted date output without leading zeros.
* **v3:**
  * High-resolution photographic background on pure black field.
  * Unsharp mask dial processing without error diffusion.
  * 250+6 palette layout.
  * Reduced `ROLEX.IMG` size from 87 KB to 63.3 KB by dynamically caching the dial directly from active VRAM.
  * Fixed clock hand rotation direction error caused by an inverted vertical Y-axis sign.
* **v2:**
  * Photorealistic dial and background based on actual watch photography.
  * Polished steel hand rendering.
  * Rendered date display in dial window.
  * Double-buffered smooth drawing (zero flicker).
  * Graphics asset loading via `int 21h`.
* **v1:**
  * Procedurally generated watch face (fluted bezel, indices, custom $8 \times 8$ bitmapped text legends, red second hand).
